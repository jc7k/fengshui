# Deployment — Vercel

The Expo web static export is hosted on Vercel. Every push to the GitHub repo
builds; non-`main` branches get preview URLs, `main` publishes production.

## Repo-side config

`vercel.json` holds everything that can live in the repo, so the dashboard needs
as few clicks as possible:

```json
{
  "framework": null,
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "cleanUrls": true,
  "trailingSlash": false,
  "rewrites": [{ "source": "/(.*)", "destination": "/" }]
}
```

- `framework: null` — Vercel's Expo/Next presets do not apply. This is a plain
  static export.
- `buildCommand` / `outputDirectory` — mirror of `npm run build` →
  `expo export --platform web` → `dist/`.
- `cleanUrls` — serves `dist/design.html` at `/design` and redirects
  `/design.html` → `/design`.
- `rewrites` — the fallback. See the next section for why it is not the whole story.

The rewrite destination is `/`, **not** `/index.html`: Vercel's docs state that
when `cleanUrls` is `true`, rewrite `source` and `destination` paths must not
carry the file extension. `/` resolves to `index.html` through the filesystem.

### Why the catch-all rewrite is a safety net, not the fix

`app.json` sets `web.output: "static"`, so the export pre-renders one HTML file
per route:

```
dist/index.html        →  /
dist/design.html       →  /design
dist/+not-found.html   →  (Expo's 404 screen)
dist/_sitemap.html     →  /_sitemap
```

That means a hard refresh at `/design` is served straight off the filesystem and
never had the expo#32139 404 problem in the first place — that failure mode is
specific to `web.output: "single"` (true SPA), where only `index.html` exists.

The catch-all rewrite is still worth keeping. Vercel applies `rewrites` **after**
the filesystem check — "precedence is given to the filesystem prior to rewrites
being applied" ([vercel.json docs](https://vercel.com/docs/project-configuration/vercel-json#rewrites))
— so it cannot shadow the pre-rendered routes; it only catches paths with no
matching file. It covers two real cases:

1. Client-side routes that are not statically pre-rendered (dynamic segments
   added later).
2. A future switch to `web.output: "single"`, which would otherwise 404 on every
   deep link.

**Known tradeoff:** an unmatched path returns HTTP **200** with `index.html`, and
Expo Router then renders the not-found screen client-side. Correct UX, wrong
status code. If a real 404 status matters later, drop the rewrite and rely on
`+not-found.html` — but that regresses case 1 above.

### canvaskit.wasm

`public/canvaskit.wasm` is gitignored (7.7MB, not source). It is regenerated by
the `postinstall` script (`setup-skia-web public`), which runs during Vercel's
`npm install`, and lands at `dist/canvaskit.wasm`. No dashboard step needed —
but if a deploy ever renders a blank canvas, check that `postinstall` ran.

## Dashboard steps (human required)

These cannot be scripted from the repo. Do them once.

1. **Push `main`** to `github.com/jc7k/fengshui`. Vercel builds from GitHub, so
   unpushed commits are invisible to it.
2. **Import the repo** at vercel.com → Add New → Project → import `jc7k/fengshui`.
3. **Framework Preset: Other.** Build Command, Output Directory and Install
   Command should be picked up from `vercel.json`; leave the dashboard overrides
   off so the repo stays the source of truth.
4. **Confirm preview deploys are on** for non-`main` branches: Settings → Git →
   Deploy Hooks / Ignored Build Step should not exclude branches. This is on by
   default.
5. **Copy the production URL and one branch preview URL** into the table above.

## Environment variables (REQ-003 and later)

None yet — this deploy has no backend. REQ-003 introduces Supabase, and preview
and production use **different Supabase projects** (PRD §6) so test data never
reaches production.

Wire them per-environment in Vercel → Settings → Environment Variables, setting
each key twice with different values and different environment scopes:

| Key | Preview | Production |
| --- | --- | --- |
| `EXPO_PUBLIC_SUPABASE_URL` | dev project URL | prod project URL |
| `EXPO_PUBLIC_SUPABASE_ANON_KEY` | dev anon key | prod anon key |

Only the **anon / publishable** key belongs here — it ships inside the client
bundle by design and is protected by RLS. The Supabase `service_role` key and the
Google OAuth client secret must never be added to this project.

The `EXPO_PUBLIC_` prefix is required for the value to be inlined into the web
bundle at export time; variables without it are dropped from the client build.
Env var changes do not apply to existing deployments — redeploy after adding them.
